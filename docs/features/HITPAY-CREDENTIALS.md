# HitPay API Credentials — What We Need From You

**Who this is for:** the business owner / account holder of the HitPay account for
Singapore Handpan Studio.
**Time needed:** ~15 minutes for Part 1 (test keys). Part 2 (live keys) depends on how fast
HitPay verifies your business.

## Why we need this

The online shop takes payment through HitPay. When a customer clicks **Buy**, our website hands
the order to HitPay, and HitPay shows its own secure payment page (PayNow QR and credit cards).
For our website to talk to your HitPay account it needs two short secret values from the HitPay
dashboard — an **API key** and a **salt**. Without them the shop cannot take money.

We need a **test (sandbox)** pair now so we can finish and test the shop safely with fake money,
and a **live (production)** pair later, just before launch.

---

> ## ⚠️ SECURITY — please read before you send anything
>
> These values are **secrets**. Anyone holding them can create charges on your HitPay account
> and forge payment confirmations.
>
> - **Do NOT** send them by email, WhatsApp, Telegram, Slack, SMS, or a shared Google Doc.
> - **DO** send them through a password-manager share (1Password, Bitwarden, Dashlane — "share
>   item" / "one-time secret link"), or another encrypted channel we agree on first.
> - If you are not sure how, say so and we will send you a one-time secret link to paste into.
> - We store them as **encrypted Cloudflare Pages secrets**. They are never written into the
>   website's code, never committed to the code repository, and never sent to the browser.
> - If a value is ever exposed by accident, tell us immediately — HitPay lets you regenerate the
>   key, and we swap it over in minutes.
>
> **Our website never sees, handles, or stores card numbers.** The card form lives on HitPay's
> own page, on HitPay's servers.

## The three values, per environment

| Name             | What it is                                                    | Where it comes from                                                           |
| ---------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `HITPAY_API_URL` | Which HitPay system to talk to                                | Fixed address — **we already know it, you do not need to look it up**         |
| `HITPAY_API_KEY` | The key proving a request came from your business             | Generated by you in the HitPay dashboard                                      |
| `HITPAY_SALT`    | A second secret used to verify HitPay's payment confirmations | Shown on the **same dashboard page** as the API key — they are a matched pair |

The API key and the salt must always come from the same page, in the same environment. A sandbox
key with a live salt (or vice versa) will not work.

# Part 1 — Sandbox keys (needed now)

Sandbox is HitPay's free practice environment. It uses fake money and fake cards, so nothing here
can cost you anything. **It is a completely separate account from your real HitPay account** —
separate signup, separate login, separate keys. One cannot be converted into the other.

### Steps

1. Go to **<https://dashboard.sandbox.hit-pay.com>** and register an account.
   Use a business email you can access. Sandbox does **not** require company documents or bank
   details.
2. Verify your email address when HitPay sends the confirmation, then log in.
3. In the left-hand menu, open the API keys page. Depending on which dashboard version your
   account is on, it is in one of two places — both lead to the same screen:
   - **Settings → Payment Gateway → API Keys**, or
   - **Payments → API Keys**
4. If no key is shown yet, click the button to **generate / create an API key**.
5. Copy **both** values from that page:
   - the **API key** (a long string of letters and numbers), and
   - the **Salt** (a second, separate long string, sometimes labelled "Salt value").
6. While you are there, open **Settings → Payment Methods** and make sure **PayNow** is set up.
   Card payments in sandbox are enabled by connecting a (test) Stripe account. If either is not
   available to you, tell us — we can test without it.
7. Send the two values to us using the secure method in the security box above. Use the fill-in
   block at the end of this document.

That is everything for Part 1. **You do not need to configure a webhook or callback URL** — our
website tells HitPay where to send confirmations on every individual order.

### Optional: try a test payment yourself

Once the shop is running against sandbox we will send you a test link. HitPay's published test
cards are:

| Card             | Number                |
| ---------------- | --------------------- |
| Visa (succeeds)  | `4242 4242 4242 4242` |
| Visa (declined)  | `4000 0000 0000 0002` |
| Mastercard       | `5555 5555 5555 4444` |
| American Express | `3782 822463 10005`   |

Any future expiry date and any 3-digit code will do.

For **PayNow** in sandbox, the checkout page shows a QR code: scan it with your phone's camera
app, which opens a page with a **PayNow** button — tapping that button marks the test payment
successful. No real money moves.

# Part 2 — Production keys (needed at launch)

Do this when we are close to going live, but **start the verification early** — HitPay's approval
is not instant.

1. Sign up for (or log in to) your real HitPay business account at **<https://www.hitpayapp.com>**.
2. Complete HitPay's business verification (KYC): business details (UEN), identity documents, and
   the bank account for payouts. HitPay's published guidance is **1–3 business days**. API keys
   are only available once the business is verified.
3. In the live dashboard, open the same page as in Part 1:
   **Settings → Payment Gateway → API Keys** (or **Payments → API Keys**).
4. Generate the live **API key** and copy the live **Salt** from the same page.
5. Under **Settings → Payment Methods**, confirm **PayNow** and **cards** are switched on — those
   are the two methods the shop offers.
6. Send us the live values using the secure method above. **Do not send them before we ask** — we
   will tell you when the launch window is set.

Live keys and sandbox keys are not interchangeable. We keep the two sets in separate Cloudflare
environments (preview vs production), so a test order can never reach your real account, and a
real order can never land in sandbox.

## About the webhook address

After a customer pays, HitPay calls our website back to confirm the order. Our site sends that
address to HitPay with every individual order, so **normally there is nothing for you to set up**.

For reference, the address is:

```
https://singaporehandpans.com/api/shop/hitpay-webhook
```

If the dashboard ever asks you to register, whitelist, or approve a callback / webhook URL, paste
that exact address. During testing it will instead be a preview address ending in `.pages.dev` —
we will send you the exact one if it is ever needed.

## If you get stuck

- **You cannot find the API Keys page.** HitPay has moved it between dashboard versions. Try both
  **Settings → Payment Gateway → API Keys** and **Payments → API Keys**. If neither exists in
  your account, send us a screenshot of your left-hand menu (no secret values visible) and we
  will point you to the right button.
- **You see two different salts.** HitPay uses one salt tied to your business API key, and a
  separate per-webhook salt for webhooks registered in the dashboard. We need the **API-key
  salt** — the one shown next to the API key. If it is ambiguous, send us both, clearly labelled,
  and we will pick the right one.
- **Sandbox signup asks for something you are not comfortable providing.** Stop and tell us —
  sandbox should not need company documents or bank details.

Screenshots are welcome for anything else. Please crop or blur the secret values before sending a
screenshot through an insecure channel.
